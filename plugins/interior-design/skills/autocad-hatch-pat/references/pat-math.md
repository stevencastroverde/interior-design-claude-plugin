# PAT File Math Reference

## Core Formula (Proven — Derived from Real Working Examples)

This formula was reverse-engineered from production .pat files generated by architextures.org and verified to work in AutoCAD. Do not deviate from it.

### Data Line Format
```
angle, x-origin, y-origin, delta-x, delta-y[, dash1, dash2, ...]
```

**Parameters:**
- `angle` — line direction in degrees (0=horizontal, 90=vertical)
- `x-origin, y-origin` — world-space origin point one line in this family passes through
- `delta-x` — displacement **along** the line between successive parallel instances (use 0 for tile patterns)
- `delta-y` — perpendicular spacing between parallel lines in this family
- `dash, gap` — positive=draw, negative=skip (omit for continuous lines)

**Critical:** For a 90° (vertical) line, `delta-y` is the **horizontal** spacing between parallel vertical lines (perpendicular to the line). This is counterintuitive but correct.

## Standard Tile Pattern Formula

### Variables
```
tile_heights[]     — height of each tile type (all same for rectangular tiles)
tile_widths[]      — width of each tile type in one horizontal row unit
grout              — grout joint width
num_rows           — number of offset rows before pattern repeats (1, 2, or 3 typically)
offset_fraction    — fraction of horiz_period to shift each row (0, 0.5, 0.333, etc.)

row_height    = tile_height + grout
horiz_period  = sum(tile_widths[i] + grout for each tile i)
offset        = horiz_period * offset_fraction
vert_repeat   = num_rows * row_height
```

### Line 1: Horizontal Grout Joints
```
0, 0, 0, 0, {row_height}
```
One line family, no dash/gap (continuous), repeats every `row_height` inches vertically.
This single line handles ALL horizontal grout joints for ALL rows.

### Lines 2+: Vertical Grout Joints (one per joint per row)
For each row `r` in range(num_rows):
  For each grout joint `j` in that row's tile sequence:

```
90, {x_joint}, {y_row}, 0, {horiz_period}, {row_height}, {gap}

where:
  x_joint = (r * offset) + sum(tile_widths[0..j] + grout * j)
  y_row   = r * row_height
  gap     = -(vert_repeat - row_height)   # negative: skip other rows
```

**Total line families** = 1 (horizontal) + (num_rows × joints_per_row)

## Worked Example: 24"×12" Field + 4"×12" Accent, 1/16" Grout, 1/3 Offset

```python
W = 24.0      # field tile width
N = 4.0       # accent tile width
H = 12.0      # both tile heights
G = 0.0625    # grout = 1/16"

row_height   = H + G           # 12.0625
horiz_period = (N+G) + (W+G)  # 28.125   (accent unit + field unit)
offset       = horiz_period/3  # 9.375
vert_repeat  = 3 * row_height  # 36.1875
dash         = row_height      # 12.0625
gap          = -(2 * row_height) = -24.125

# Row A (r=0): y_row=0, x_shift=0
#   Joint 1 (right of accent): x = 0 + 4.0 = 4.0
#   Joint 2 (right of field):  x = 0 + 4.0625 + 24.0 = 28.0625

# Row B (r=1): y_row=12.0625, x_shift=9.375
#   Joint 1: x = 9.375 + 4.0 = 13.375
#   Joint 2: x = 9.375 + 4.0625 + 24.0 = 37.4375

# Row C (r=2): y_row=24.125, x_shift=18.75
#   Joint 1: x = 18.75 + 4.0 = 22.75
#   Joint 2: x = 18.75 + 4.0625 + 24.0 = 46.8125
```

**Output .pat file:**
```
*TILE_24X12_ACCENT, 24x12 Field + 4x12 Accent Tile | 1/16 Grout | 1/3 Offset
0, 0,0, 0,12.0625
90, 4.0,0, 0,28.125, 12.0625,-24.125
90, 28.0625,0, 0,28.125, 12.0625,-24.125
90, 13.375,12.0625, 0,28.125, 12.0625,-24.125
90, 37.4375,12.0625, 0,28.125, 12.0625,-24.125
90, 22.75,24.125, 0,28.125, 12.0625,-24.125
90, 46.8125,24.125, 0,28.125, 12.0625,-24.125

```

## Worked Example: Simple Running Bond (1/2 offset)
Tile: 12"×4", Grout: 3/16"

```
row_height   = 4 + 0.1875 = 4.1875
horiz_period = 12 + 0.1875 = 12.1875
offset       = 12.1875 / 2 = 6.09375
vert_repeat  = 2 * 4.1875 = 8.375
dash         = 4.1875
gap          = -(8.375 - 4.1875) = -4.1875

# Row A (r=0): joint at x = 12.0 (right edge of tile)
# Row B (r=1): joint at x = 6.09375 + 12.0 = 18.09375
```

```
*RUNNING_BOND_12X4, 12x4 Running Bond | 3/16 Grout | 1/2 Offset
0, 0,0, 0,4.1875
90, 12.0,0, 0,12.1875, 4.1875,-4.1875
90, 18.09375,4.1875, 0,12.1875, 4.1875,-4.1875

```

## Worked Example: Stack Bond (no offset)
Tile: 6"×6", Grout: 1/8"

```
row_height   = 6 + 0.125 = 6.125
horiz_period = 6 + 0.125 = 6.125
vert_repeat  = 1 * 6.125 = 6.125  (num_rows=1)
dash         = 6.125
gap          = -(6.125 - 6.125) = 0  → but gap=0 means dotted!

# Stack bond has no stagger, so each vertical line repeats continuously.
# Use a VERY large gap to represent a single tile height, OR...
# For stack bond, simpler approach: just two continuous line families.
```

**Stack bond special case** — for stack bond (no offset, uniform tile), you only need 2 families:
```
*STACK_6X6, 6x6 Stack Bond | 1/8 Grout
0, 0,0, 0,6.125
90, 6.0,0, 0,6.125

```
No dash/gap on the 90° line — it's continuous because joints align every row.

## Naming Rules

Pattern name constraints (AutoCAD will reject if violated):
- Maximum **31 characters**
- No spaces (use underscores)
- No slashes (`/` or `\`)
- No parentheses or brackets
- No punctuation except `-` and `_`
- No special/non-ASCII characters
- Case insensitive in practice, but use ALL_CAPS by convention

Good names: `TILE_24X12_ACCENT`, `RUNNING_BOND_4X12`, `HERRINGBONE_3X12`
Bad names: `My Custom Tile (4")`, `tile/brick`, `24x12+accent`

## Herringbone Pattern

Herringbone is substantially more complex. It requires diagonal lines (45° or other angles) and careful repeat vector calculation.

**Key principle:** Find the smallest rectangular repeat cell. For a standard 2:1 herringbone (tile 2× as wide as tall):
- A 90° herringbone uses tiles at 0° and 90° within each cell
- The repeat cell is tile_width × tile_width (square)
- Requires 4+ line families

Example: 8"×4" herringbone, no grout:
```
*HERRINGBONE_8X4, 8x4 Herringbone
0, 0,0, 4,4, 8,-8
90, 8,0, -4,4, 8,-8

```
Where `delta-x=4, delta-y=4` creates the diagonal tiling repeat.

For grout in herringbone, add grout/2 as an origin inset on each line.
For 45° herringbone, rotate all coordinates by 45° — multiply x by cos(45°) and y by sin(45°).

**Herringbone is an advanced case** — if the user requests it, work through the geometry carefully and test iteratively.

## File Writing — Python Template

Always use this exact Python to write the file:

```python
def write_pat_file(pattern_name, description, line_defs, output_path):
    """
    pattern_name: str, ≤31 chars, no spaces/slashes
    description:  str, human-readable
    line_defs:    list of strings, each a complete data line
    output_path:  str, full path ending in .pat
    """
    lines = [f"*{pattern_name}, {description}"]
    lines.extend(line_defs)
    lines.append("")  # mandatory trailing blank line
    content = "\r\n".join(lines) + "\r\n"
    
    # Verify ASCII
    assert all(ord(c) < 128 for c in content), \
        f"Non-ASCII chars: {[c for c in content if ord(c) >= 128]}"
    
    with open(output_path, 'w', newline='') as f:
        f.write(content)
    
    return content
```

## Common Mistakes and Fixes

| Symptom | Likely Cause | Fix |
|---|---|---|
| Pattern not found in AutoCAD | Non-ASCII char or missing trailing blank line | Check with `python3 -c "data=open('f.pat','rb').read(); print(all(b<128 for b in data))"` |
| Lines cross tile faces instead of borders | x_joint miscalculated (missing grout or wrong tile width accumulation) | Recalculate: x_joint should be at the RIGHT edge of each tile, not center |
| Lines continuous instead of per-tile | gap too small or sign wrong | gap must be negative and large enough to skip all non-active rows |
| Pattern shifts incorrectly between rows | x_shift uses wrong formula | x_shift = row_index × offset_fraction × horiz_period |
| AutoCAD rejects with "too dense" error | Pattern very fine (small grout, many tiles) | Tell user to run `(setenv "MaxHatch" "10000000")` in AutoCAD console |
| Vertical lines appear in wrong rows | y_row calculated incorrectly | y_row = row_index × row_height (not tile_height) |
